## Phase C — Firmware fixes (`03-revamp-master.md` §3.2/§3.3, `docs/planning/11-audit-findings.md`)

### Hardware revision 4.0.0 — board constraint + load rebalance (2026-08-25, user-directed)

- [x] **GPIO36/39 removed from the design — they do not exist on the boards actually in use.** Rev 3 put two ultrasonic ECHO lines there precisely because they are input-only. Moved to **GPIO34/35**, which are also input-only, so the property that made 36/39 correct is preserved rather than compromised. Bin-bottom moved to TRIG 25 / ECHO 26.
- [x] **The two boards are now balanced, by subsystem rather than by convenience.** Rev 3 was lopsided — A had eleven jobs, B had four ADC reads, which wasted a whole microcontroller. - [x] **This is what makes eight analog channels possible at all.** With GPIO36-39 gone, ADC1 offers only four usable channels (32/33/34/35), and ADC2 is unusable whenever WiFi is active. ### Hardware revision 3.0.0 — ESP32 + ESP32 (2026-08-20, user-directed)

- [x] **The Raspberry Pi Pico co-processor is replaced by a second ESP32** (`esp/esp32_sensor`). Directed by the user; the engineering justification turned out to be stronger than "one part number." Four ports x (V+I) = **eight** analog channels, and one ESP32 cannot supply eight trustworthy ones — ADC2 is unusable while WiFi is active, and ADC1 realistically offers six. The old split therefore parked **SW4's current on ADC2/GPIO12**, where it read a permanent **0.00 A** with WiFi up: **port 4 has never had working overcurrent protection.** Splitting the eight channels across two ESP32s puts every one on an ADC1. **Nothing uses ADC2 now**, and GPIO12 — the MTDI strapping pin, which must be LOW at boot or the chip picks the wrong flash voltage — is free.
- [x] **New split:** ESP32-A (WiFi ON) reads SW1+SW2 on its ADC1; ESP32-B (WiFi **never started**) reads SW3+SW4 on its ADC1 and streams `SW3V,SW3I,SW4V,SW4I` over UART2 every 500 ms. Four values, not the Pico's three — a parser expecting exactly four rejects a stale three-field line, so a half-upgraded bench fails loudly instead of silently mis-assigning ports. Calibration constants stay only on A, so recalibration reflashes one board.
- [x] **WiFi reset button added — GPIO22, hold 3 s.** Erases stored credentials from NVS and reboots into the provisioning AP. Closes a real operational hole: the provisioning AP was previously only reachable when stored credentials *failed*, so a kiosk holding valid-but-wrong credentials (network renamed, password rotated) could only be recovered by physically retrieving and reflashing it. GPIO22 chosen because it is the only free **non-strapping** pin — a button on GPIO0/2/12/15 held during a power cut could stop the kiosk booting. Ignores a button already held at boot until released once, so a stuck button cannot wipe credentials every power-on; does **not** reboot if the NVS erase fails.
- [x] **Both firmwares compile clean** — real `pio run` on each (ESP32-A: 25.5% flash, 10.7% RAM; ESP32-B: 5.3% flash, 3.5% RAM). One real compile error was found and fixed in the process (`wifi_reset.h` needed `<stdbool.h>`).
